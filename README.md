# 텔레그램 일일·주간 채팅 순위 봇

웹 관리자 없이 Railway에서 계속 실행되는 간단한 채팅 집계 봇입니다.

## 명령어

- `.일일순위` — 오늘 채팅 순위 1~4위
- `.주간순위` — 이번 주 채팅 순위 1~4위와 상금
- `.나` — 내 일일·주간 채팅 수와 현재 등수
- `.도움말` — 명령어 안내

## 픽 전체 전송

픽 전송은 봇과의 **개인채팅**에서만 작동하며, Railway의
`PICK_ADMIN_USER_IDS`에 등록된 관리자만 사용할 수 있습니다.

1. 봇 개인채팅에서 `/내아이디`를 보내 고유번호를 확인합니다.
2. Railway Variables에 아래처럼 고유번호를 등록하고 재배포합니다.

   ```text
   PICK_ADMIN_USER_IDS=123456789
   ```

3. 봇 개인채팅에서 고정할 프리미엄 이모지를 한 번 저장합니다.

   ```text
   /픽이모지설정 [프리미엄 이모지]
   ```

4. 이후 아래처럼 보내면 등록된 모든 소통방에 같은 픽이 전송됩니다.

   ```text
   /픽 오늘의 추천픽 내용
   ```

고정 프리미엄 이모지는 PostgreSQL에 저장되어 Railway가 재시작되어도
유지됩니다. 다른 이모지로 바꾸려면 `/픽이모지설정`을 다시 사용하면 됩니다.
봇을 만든 텔레그램 계정에 Premium 구독이 있어야 봇이 프리미엄 이모지를
직접 전송할 수 있습니다.

## 주간 순위 자동 전송

- `WEEKLY_BROADCAST_INTERVAL_HOURS`에 설정한 시간 간격마다 등록된 모든
  소통방에 주간 순위를 자동 전송합니다.
- `1`은 1시간마다, `2`는 2시간마다, `3`은 3시간마다 전송합니다.
- 변수를 추가하지 않거나 비워두면 기본값은 1시간입니다.
- 봇이 시작되거나 재시작된 시점부터 설정한 시간이 지난 뒤 첫 자동
  전송이 실행됩니다.
- 봇 배포 후 각 소통방에서 채팅이나 명령어를 한 번 보내면 자동 전송 대상에 등록됩니다.
- Railway가 재시작되어도 PostgreSQL에 저장된 소통방 목록을 다시 불러옵니다.

Railway의 봇 서비스에서 **Variables**를 열고 원하는 시간을 설정한 뒤
재배포하면 됩니다.

```text
WEEKLY_BROADCAST_INTERVAL_HOURS=2
```

## 출력 형식

### `.일일순위`

```text
📅 일일집계

1위 - 닉네임 (@아이디) [ 120회 ]
2위 - 닉네임 (@아이디) [ 90회 ]
3위 - 닉네임 (@아이디) [ 70회 ]
4위 - 닉네임 (@아이디) [ 50회 ]

매일 00시 새로 집계
```

### `.주간순위`

```text
📆 주간집계

1위 10만 - 닉네임 (@아이디) [ 500회 ]
2위 5만 - 닉네임 (@아이디) [ 400회 ]
3위 3만 - 닉네임 (@아이디) [ 300회 ]
4위 2만 - 닉네임 (@아이디) [ 200회 ]

매주 월요일 포인트지급
주간 누적 입금 10만 원 이상 시 지급
문의 : @TB935 , @tigertk52
```

참여자가 4명보다 적어도 1~4위 줄은 항상 표시되며 빈 등수는
`집계 없음 [ 0회 ]`로 나옵니다.
텔레그램 아이디를 설정하지 않은 회원은 `(아이디 없음)`으로 표시됩니다.
회원 아이디와 문의 아이디는 클릭 가능한 프로필 링크로 표시되지만,
메시지 아래의 링크 미리보기 카드는 나오지 않습니다.

## 집계 규칙

- 일일 집계: 한국시간 매일 00시부터 새로 집계
- 주간 집계: 한국시간 매주 월요일 00시부터 새로 집계
- 공백을 제외하고 5글자 이상인 메시지만 집계
- 초성·자음만 있는 메시지와 이모지만 있는 메시지는 제외
- 같은 사람이 3초 안에 연속 작성한 메시지는 제외
- 60초 안에 같은 내용을 반복하면 제외
- 관리자도 일반 회원과 동일하게 집계
- `EXCLUDED_USER_IDS`에 넣은 사용자 고유번호만 제외

## 특정 고유번호 집계 제외

Railway의 봇 서비스에서 **Variables**를 열고 아래 변수를 추가합니다.

```text
EXCLUDED_USER_IDS=123456789,987654321
```

여러 명은 쉼표로 구분합니다. 비워두면 관리자까지 전부 집계됩니다.
변수를 바꾼 뒤에는 봇 서비스를 재배포해야 적용됩니다.

## BotFather 설정

1. `@BotFather`에서 봇을 선택합니다.
2. `/setprivacy`를 누릅니다.
3. 해당 봇을 선택하고 **Disable**로 변경합니다.
4. 봇을 소통방에 추가합니다.

Privacy Mode를 끄지 않으면 일반 채팅을 받을 수 없어 집계되지 않습니다.

## Railway 배포

1. 프로젝트를 GitHub 저장소에 업로드합니다.
2. Railway에서 저장소를 연결해 서비스를 만듭니다.
3. PostgreSQL 서비스를 추가하고 봇 서비스에 연결합니다.
4. 봇 서비스의 Variables에 `BOT_TOKEN`을 추가합니다.
5. 필요하면 `EXCLUDED_USER_IDS`, `PICK_ADMIN_USER_IDS`,
   `WEEKLY_BROADCAST_INTERVAL_HOURS`도 추가합니다.
6. 배포 후 로그에서 `Bot started as`가 뜨는지 확인합니다.

관리 웹은 없으며 Railway Healthcheck용으로 모든 경로에서 `OK`만 반환합니다.
기존 Healthcheck Path와 Public Domain이 남아 있어도 배포할 수 있습니다.
`ADMIN_USERNAME`, `ADMIN_PASSWORD`는 필요하지 않습니다. `PORT`는 Railway가
자동으로 넣으므로 직접 설정할 필요가 없습니다. 시작 명령어가 자동으로
잡히지 않으면 서비스의 **Custom Start Command**에 아래 값을 넣습니다.

```text
python -m chat_rank_bot
```

## 환경변수

| 이름 | 기본값 | 설명 |
|---|---:|---|
| `BOT_TOKEN` | 필수 | BotFather 토큰 |
| `DATABASE_URL` | `sqlite:///data/chat_rank.db` | Railway PostgreSQL 또는 SQLite 주소 |
| `TIMEZONE` | `Asia/Seoul` | 집계 시간대 |
| `EXCLUDED_USER_IDS` | 빈 값 | 집계하지 않을 사용자 고유번호 |
| `PICK_ADMIN_USER_IDS` | 빈 값 | 개인채팅 픽 전송을 허용할 사용자 고유번호 |
| `WEEKLY_BROADCAST_INTERVAL_HOURS` | `1` | 주간 순위 자동 전송 간격(시간) |
| `MIN_TEXT_LENGTH` | `5` | 최소 글자 수 |
| `MIN_MESSAGE_INTERVAL_SECONDS` | `3` | 연속 채팅 제외 시간 |
| `DUPLICATE_WINDOW_SECONDS` | `60` | 같은 내용 반복 제외 시간 |
